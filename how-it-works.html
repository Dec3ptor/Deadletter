What is hidden, what is not, and what this cannot do.

A dead letter is mail nobody can deliver and nobody may open. That is the idea here: the board is public, the posts are not, and the site itself has no way in.

The short version

Every thread has a code. Your browser turns that code into a key and seals each post with it before the post goes anywhere. What gets stored is sealed. It cannot be read without the code, and the code is never sent, never logged and never kept.

Lose the code and the thread is gone. Not recoverable by us — there is no “us” in the loop, only bytes nobody holds the key to.

What is hidden

  • Everything written inside a thread.
  • Every image and file attached to a post.

What is not

  • The thread title. The list has to show something. Do not put the secret in the title.
  • The shape of the conversation. How many posts a thread holds, roughly how long each is, and when each arrived. Someone can watch a thread grow busy without reading a word of it.
  • That the thread exists at all. If that is the thing you need hidden, this is the wrong tool.

The code is the whole of it

Press Generate and you get a 256-bit key — genuinely random, and strong enough that guessing it is not a plan anyone can carry out. That is the one to use.

You may type your own instead, and each guess against it is made deliberately slow. That helps, but it cannot save a code someone could think of. Everything stored here can be copied by anyone as sealed bytes, so a person can take that copy away and guess at it privately, for years, and nobody would ever know they were trying. A memorable phrase does not survive that. A generated key does.

Who wrote what

Posts are labelled Anonymous 1, Anonymous 2 and so on, numbered by the order people first appear in the thread. Everyone holding the code sees the same numbers, so a conversation can be followed.

The label is sealed with the post like everything else — without the code there is nothing to see. And because nothing is kept on your machine, the identity lasts as long as the tab: reload, and your next post is a new number. There are no accounts here to be recognised by.

Pictures and video wait to be asked for

Opening a thread does not fetch what is in it. Each attachment travels with a small sealed preview, so reading a thread of photographs costs a few kilobytes rather than a few megabytes, and the original is only ever fetched when you click to see it full size.

The switch beside the composer turns even the previews off, so nothing is unsealed until you press Show on the one you want. Attachments at the top of a thread gathers everything ever posted to it into one grid, under the same rule.

Searching a thread

An open thread can be searched by word, and by what is attached — type:image, type:video, type:gif, or has:file for anything at all. Words match what was written and the names of the files.

The search runs entirely in front of you, on what your browser has already unsealed. Nothing about it is sent anywhere, and a sealed thread cannot be searched at all — there is nothing there but bytes until the code is entered.

Everyone with the code is equal

There are no accounts and no owners. Anyone holding the code can read the thread and post to it. A code cannot be taken back once given, and it cannot be changed — the only way to shut someone out is to start a new thread with a new code and not give them that one.

Nothing can be edited or deleted afterwards, including by whoever wrote it. That is a real cost, and it buys something: nobody wandering past can erase anyone else's thread.

Nothing is kept on your machine

No cookies. Nothing in browser storage. Not the code, not the key, not the words you just read. Close the tab and there is nothing to clear afterwards, because nothing was put anywhere.

The cost is deliberate: every visit starts sealed and every thread has to be unlocked again. The alternative is a key sitting on a disk, outliving whoever typed it, on a shared computer or a laptop that ends up in someone else's hands.

Would a quantum computer break it?

No — for a dull structural reason rather than a clever one. The attacks people worry about, the ones that would break banking and web certificates outright, work against a particular kind of maths that is not used here at all. There is nothing for them to take apart.

The one quantum attack that does apply effectively halves the strength of a key. That is exactly why a generated code is 256 bits and not 128: halve it and what remains is still far out of reach.

The caveat matters more than the claim. Everything here is public, so anyone can take a copy today and work on it indefinitely — waiting for better computers is a real strategy. A code you invented is guessable on that timescale. A generated one is not.

What this does not protect you from

  • Anyone you gave the code to. It is read and write access at once, permanent, and it cannot be revoked.
  • Your own device. Everything is unsealed on the machine in front of you. If that machine is compromised, so is anything you open on it.
  • Being watched. When you posted, and roughly how much, is visible even though the content is not.
  • A code that leaks later. Whoever learns it next year can read everything ever posted. There is no way to seal off the past.
  • Someone copying what they read. Obvious, but worth saying: this decides who can read, never what a reader does next.

Checking rather than trusting

A sealed thread shows you the real stored bytes before you enter the code — what is on screen is exactly what is held, not a stand-in drawn to look convincing. And the site is open source, so what this page claims can be read against the code that does it rather than taken on faith.
